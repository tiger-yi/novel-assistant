# World Bible 归档执行规范 (Archiving Rules)

## INV-ARCHIVE-001 授权、触发与歧义熔断

归档必须获得人工指令授权，或获得完整章节事务携带的一次条件授权；同时满足人工强制、周期、卷终或实体离场触发之一。执行前必须生成明确迁移预览，存在事实冲突、无法判重、范围扩大或目标不明确时不得迁移，只记录 `ARCHIVE_PENDING`。

## 1. 触发判定
- **卷终(Arc Complete)**: `outline.md` 中某卷标记为 `[已完成]`。
- **周期(Cycle)**: 每满 10 章进行一次归档触发；不足 10 章不归档。
- **强制(Manual)**: 用户输入 `归档世界`。
- **条件(Conditional)**: `创作第 N 章` 完成 Postflight 后到期，且迁移预览无歧义。

`创作第 N 章` 构成一次条件归档授权，不代表每章都迁移。预览存在冲突、重复无法判定、范围扩大或目标不明确时，保持归档文件不变并记录 `ARCHIVE_PENDING`；章节主体事务仍可完成。

## 2. 细则说明与主文件保留方案

归档的核心原则是：**主文件必须保持轻量化，但不能丢失历史索引。** 所有的归档操作完成后，必须在原主文件中留下对应的“归档链接”，以便 Agent 追溯。规范中的 `archive/...` 示例按写入 `world/*.md` 后的相对路径解释。

迁移时必须保留章节/实体 ID；归档目标已有相同 ID 或章节区间时不得重复追加。活跃文件中的索引同时记录 ID/区间和锚点链接。Agent 只准备迁移预览与 staging 候选，正式归档目标和活跃索引只能由事务执行器按基线摘要发布。

每次归档判断都必须提交 `archive-integrity` 语义门禁：实际迁移时逐项证明来源 ID/章节区间、目标判重结果、活跃索引和归档锚点；未到期或存在歧义时使用附原因的 `NOT_APPLICABLE`，并分别记录 `NOT_DUE` 或 `ARCHIVE_PENDING`。执行器还会在写入前后验证本地 Markdown 链接目标存在。

### 2.1 `outline.md` (剧情大纲)
- **归档对象**: 将已完成的“10 章块”或“完整卷”的详细章节规划表剪切至 `archive/outline_history.md`。
  - **注意**：每满 10 章触发归档，但这不等于一卷的结束（一卷可能有 15、27 章等）。因此，10 章块归档应以“章节区间”（如 `#第1-10章`）为锚点；若恰逢整卷结束，则可以“卷名”或“全卷区间”归档。
- **主文件保留方案**: 在详细章节规划表中，用一行归档记录替换原有的多行章节列表。包含“章节区间”、“(已归档)”、“一句话梗概（总结该段剧情核心事件）+ 存档链接”等信息。
- **主文件示例**:
  ```markdown
  | 章节 | 标题 | 核心事件 | 悬念钩子 | 状态 |
  | :--- | :--- | :--- | :--- | :--- |
  | **第1-10章** | **(已归档)** | > **核心梗概**：苏铭觉醒系统，完成平安公寓、乱葬岗送外卖、阳光小区404凶宅试睡等任务，获取原始资本，拒绝官方招揽后接取黑市猩红悬赏。<br>> 🔗 **详细章节规划已归档至**：[archive/outline_history.md#第1-10章](archive/outline_history.md) | - | ✅ 已完成 |
  ```

### 2.2 `hooks.md` (叙事线索注册表)
- **归档对象**:
  1. 将状态为 `已解决` 或 `已放弃` 的 `HOOK-*` 迁移至 `archive/hooks_history.md`。
  2. 将状态为 `已回收` 或 `已取消` 的 `SEED-*` 迁移至 `archive/hooks_history.md`。
- **主文件保留方案**: 从活跃表移除终态条目，在已归档索引中保留叙事线索 ID、一句话结果和归档链接。归档记录必须保留 `foreshadowing-spec.md` 要求的全部状态跃迁证据。
- **主文件示例**:
  ```markdown
  ## 已归档叙事线索索引

  - `HOOK-0011`: 门后身份已在 `CH-0013` 解决。[归档记录](archive/hooks_history.md#hook-0011)
  - `SEED-0007`: 红线真相已在 `CH-0048` 回收。[归档记录](archive/hooks_history.md#seed-0007)
  ```

### 2.3 `chapter-summary.md` (章节摘要)
- **归档对象**: 每次触发归档时，迁移主文件中 **除最近 3 章以外** 的所有历史章节摘要至 `archive/chapter_summary_history.md`。
- **主文件保留方案 (上下文缓冲池)**: 执行归档后，主文件保留最新的 3 章摘要。归档执行前允许暂时超过 3 章，不得为了维持窗口而绕过人工或条件归档授权。
  - *例如*：写完第10章触发归档时，归档第 1-7 章，主文件保留 8-10 章。
  - *例如*：写完第20章触发归档时，主文件中有 8-20 章，则归档第 8-17 章，主文件保留 18-20 章。
  - 归档掉的章节块折叠为一个连贯的区间索引链接。
- **主文件示例** (假设刚写完第10章并完成归档):
  ```markdown
  ## 章节摘要
  > **第001章 - 第007章**: 🔗 已归档至 [archive/chapter_summary_history.md#第1-7章](archive/chapter_summary_history.md)

  ### 第008章：停尸房的午夜巡更
  （摘要内容...）

  ### 第009章：诈尸与狂暴镇压
  （摘要内容...）

  ### 第010章：血色规则的漏洞
  （摘要内容...）
  ```

### 2.4 `characters.md` (人物档案)
- **归档对象**: 将 `status` 为“已死亡”、“已消失”或“长期离场”的角色迁移至 `archive/characters_registry.md`。
- **主文件保留方案**: 在各势力或分类的末尾，或者在文件底部建立一个 `## 历史人物索引`，仅保留角色名、最终状态和归档链接，不保留任何数值与背景设定。
- **主文件示例**:
  ```markdown
  ## 历史人物索引 (已归档)
  - **李四** [已死亡] - 原青云宗外门长老。 🔗 [查看档案](archive/characters_registry.md#李四)
  ```

### 2.5 `timeline.md` (时间线)
- **归档对象**: 将已完成卷中**非里程碑（Milestones）**的详细事件条目迁移至 `archive/timeline_chronicles.md`。
- **主文件保留方案**:
  - **强制保留**: 只有被标记为 `**[里程碑]**` 的条目（通常为境界突破、核心反派伏诛、重大地图切换）才允许留在主文件。
  - **剪切要求**: 一旦卷标题标记为 `[已归档]`，主文件中该卷下的所有非里程碑条目必须**物理删除（剪切）**，并替换为对应的归档锚点链接。如果卷标题未被标记为`[已归档]`，只保留最新的10个时间线条目和核心里程碑，其余条目所有非里程碑条目必须**物理删除（剪切）**，并替换为对应的归档锚点链接
- **主文件示例**:
  ```markdown
  ## 1. 卷一：荒村雷鸣 [已归档]
  - **[元年/正月] - **[里程碑]** 天师重生。
  - **[元年/二月] - **[里程碑]** 斩杀异化县令，平安县城覆灭。
  > 🔗 **卷一详细琐碎事件记录**：已归档至 [archive/timeline_chronicles.md#卷一](archive/timeline_chronicles.md)
  ```

### 2.6 `inventory.md` (道具与功法)
- **归档对象**:
  1. **已消耗/损毁 (Depleted/Broken)**: 
     - 数量归零的消耗品（如：丹药、符箓、消耗性材料）。
     - 状态标识为“枯竭 (Depleted)”且无自动恢复能力的资源（如：真阳涎/心头血等主角本源）。
     - 彻底损毁且无修复计划/价值的法宝、凡兵（如：林大勇的短匕）。
  2. **过时/临时情报 (Temporary Intel)**:
     - 标记为“已掌握”且不涉及后续核心主线的临时线索（如：特定章节的布防图、临时暗记）。
     - 具有时效性且已失效的路径、锚记（如：仅限当夜有效的“暗渠因果小径”）。
     - 已转化为更高位格结论的原始物证（如：已导出因果码的原始负片）。
  3. **遗弃物 (Discarded Items)**: 主角主动丢弃或遗忘在旧地图的低阶道具。
- **主文件保留方案**:
  - **活跃清单**: 仅保留“当前持有”、“正在修炼”、“关键未解情报”以及“具备进阶潜力的核心法宝”。
  - **情报聚合 (Intel Consolidation)**: 在 `## 4. 情报与地图` 底部增加一个 `### 历史情报归档索引`，按“卷/剧情块”提供聚合链接，移除原始散乱的表格条目。
- **主文件示例**:
  ```markdown
  ## 4. 情报与地图
  ... (活跃情报表格) ...

  ### 历史情报归档索引
  - **[第一卷：归墟初醒]**: 🔗 已归档 15 条临时线索（含布防图、家庙残纹、临时锚记等）。[查看详情](archive/inventory_logs.md#卷一情报)

  ## 历史消耗记录
  > 🔗 本主角一路走来所消耗的丹药、损毁的法宝及遗弃的低阶物品，请查阅：[archive/inventory_logs.md](archive/inventory_logs.md)
  ```

### 2.7 `geography.md` (地理与势力)
- **归档对象**: 将主角已离开且无活跃叙事线索（关联 `HOOK-*` 与 `SEED-*` 数量均为 0）的旧地图详情迁移至 `archive/world_atlas.md`。
- **主文件保留方案**: 保留地图层级结构（比如某个大洲下的小国家），但将详细描述、特产、NPC列表全部删除，替换为一行状态说明与链接。
- **主文件示例**:
  ```markdown
  ### 青云宗 (东荒南域)
  > **状态**：主角已离开，当前无活跃叙事线索。
  > 🔗 **详细区域志/历史设定**：已归档至 [archive/world_atlas.md#青云宗](archive/world_atlas.md)
  ```

## 3. 归档目录结构
```
world/archive/
├── outline_history.md      # 剧情大纲历史存档
├── hooks_history.md        # 钩子与伏笔回收历史
├── chapter_summary_history.md # 章节摘要历史
├── characters_registry.md  # 死亡/离场人物登记簿
├── timeline_chronicles.md  # 历史时间线长卷
├── inventory_logs.md       # 道具消耗/损毁记录
└── world_atlas.md          # 旧地图/已探索区域志
```
