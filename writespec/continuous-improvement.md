# 受控改进规范

本规范定义 Novel Assistant 如何从失败、纠正和恢复事件中形成可审计的改进提案。受控改进只产生候选知识，不授予 Agent 自动修改正式规则的权限。

## 1. 改进提案

改进提案使用稳定 ID `IMP-NNNN`，统一记录在 `novel-harness/improvement-log.md`。编号取台账历史最大编号加一，已拒绝或已晋升的编号不得复用。

提案本身不具备约束力，不得被章节创作、世界更新或验证流程当作正式规则执行。

## 2. 触发条件

仅在以下事件发生时生成提案：

- 用户明确纠正 Agent 的行为或领域理解。
- 同类失败在两个独立任务中重复出现。
- 确定性门禁与权威规范产生矛盾。
- 为完成任务连续两次采用相同人工补救步骤。
- 事务恢复暴露出规范未覆盖的状态。

普通成功、一次性笔误和纯创作偏好不生成提案。新增前必须按问题、根因和建议去重。

## 3. 生命周期

`候选 -> 已验证 -> 已晋升` 是正常路径；证据不足、已有规则覆盖或收益小于复杂度时转为 `已拒绝`。

### 3.1 候选

记录触发事件、文件或命令证据、问题、根因假设和建议。生成候选不阻断当前任务。

### 3.2 已验证

至少满足以下一项：

- 问题可以稳定复现。
- 自动化测试证明规则缺口。
- 两次独立事件提供一致证据。

无法验证时不得描述为 Agent 已经“学会”。

### 3.3 晋升

用户必须明确批准晋升及目标类型。晋升变更应在同一变更集中更新权威文件、Manifest 路由、必要引用和测试；相关验证通过后，才把提案标记为 `已晋升` 并链接目标。

## 4. 晋升分类

- **普通规范**：可执行但不构成全局阻断的流程、阈值或建议。
- **不变量 (INV)**：违反即必须阻断流程的稳定规则；必须定义权威规范、适用范围和验证证据。
- **ADR**：难以逆转、缺少上下文会令人意外且存在真实取舍的架构决策。

普通经验不得膨胀为 INV，检查项不得仅因重要就记录为 ADR。

## 5. 自动化阻断分级

普通章节创作、润色、读者评价、World Bible 回写、归档和原创性修复中，发现阻断时必须先按四档分类，减少不必要人工介入：

- `AUTO_FIX`: 当前事务授权内可直接自动修复的问题，例如标题重名、字数不足或超限、格式呈现违规、L1/L2 文本工业感、低风险节奏和情绪修复。修复后必须复跑受影响门禁。
- `AUTO_ROUTE_COMMIT`: 当前阶段不能直接修，但可自动进入正确命令流程生成候选、完成验证并由事务执行器提交的问题，例如未发布章节结构重做、签约首感 `L3-ROUTE-AUTO` 的单章候选、由正文证据支撑的普通 World Bible 状态回写、无歧义条件归档。
- `AUTO_ROUTE_REVIEW`: 可自动生成候选和验证证据，但提交前必须展示预览并等待确认的问题，例如调整未发布后续章节契约、卷级结构疲劳、可能影响核心卖点的金手指呈现、归档范围扩大或合并歧义。
- `HUMAN_REQUIRED`: 生成或提交前必须先取得用户确认的问题，例如推翻题材、改冻结卷目标、改全书终局、改 World Bible 核心设定、改已发布事实、放弃钩子、取消伏笔或接受第一章前/周期原创性长期风险。

`AUTO_ROUTE_COMMIT` 不是跳过授权。它只能在 Manifest 已注册命令、对应命令写入范围允许、事务执行器基线和全部门禁通过时提交。任何缺少证据、路径越权、基线冲突或目标超出命令授权的问题，必须升级到 `AUTO_ROUTE_REVIEW` 或 `HUMAN_REQUIRED`。

## 6. ADR 与 INV 演进

- ADR 保留历史理由；改变决策时新增 ADR，并通过 `deprecated` 或 `superseded by ADR-NNNN` 建立替代关系。
- INV 只在一个 Manifest 注册的权威规范中定义，其他文件只引用稳定 ID。
- 新增或修改 INV 必须同时说明阻断场景、适用范围和验证方式，并检查 Manifest 与相关测试。
- 废弃 INV 不复用原 ID；保留废弃原因和替代规则。
- 可配置策略、普通阈值和可修复警告不得定义为 INV。

## 7. 加载策略

本规范和改进台账仅在规则维护、人工复盘或命中触发条件时加载，不加入普通章节创作的 World Bible 上下文。
