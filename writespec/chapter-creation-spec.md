# 单章创作工作流

`创作第 N 章` 自动执行完整流程；`构思第 N 章` 只执行构思与逻辑审计并停止。

## 不变量

### INV-CHAPTER-001 正文呈现边界

staging、正式正文及其历史呈现修订必须同时满足以下规则：

1. **禁止面板化符号**：无例外禁止 `【】`、`[]`、`（）`、`《》`、Markdown 标题/列表/表格和加粗标记；非对话不得使用引号。
2. **禁止内部代号**：正文不得出现 `CH-*`、`ARC-*`、`HOOK-*`、`SEED-*`、`EVT-*`、`TX-*`、`CHAR-*`、`ITEM-*`、`LOC-*`、`FAC-*`、`GOAL-*`、`MS-*` 等 Harness ID，也不得出现大小写不限的裸字母数字代号，如 `R16`、`C-12`、`n-07` 或 `room12`。允许“七号矿井”“甲字三号牢房”等自然中文称谓。
3. **禁止章节结构引用**：正文不得出现 `第X章`、`上一章`、`上章`、`本章`、`下一章`、`下章`、`前文` 或 `后文`；必须改写为具体时间、事件或自然承接。
4. **禁止叙事层泄漏**：正文不得暴露作者、读者、剧情安排、创作过程或外部镜头调度。确定性模式之外的“读者应该已经发现”“作者暂且不表”“剧情需要”“镜头转回主角”等表达由 `narrative-integrity` 语义门禁判断。

确定性校验必须报告本 INV ID、行号和命中项；语义门禁只接受 `PASS`。命中后由 Agent 结合上下文重写，最多三轮，不得盲目替换。已发布章节只能通过 `迁移正文呈现` 的授权子事务做等义呈现修订，不得改变剧情事实。

### INV-PLOT-001 冻结大纲契约

`world/outline.md` 必须包含状态为 `frozen` 的 `novel-harness/outline/v2` 契约：全书卷路线图使用连续且固定的章节闭区间，当前卷具有可验收卷目标、3-5 个带截止章节的有序里程碑，以及覆盖整卷的章节执行契约。章节事务必须绑定开始时的大纲修订号、正式文件摘要、所属卷、卷目标、章节 ID 和章节契约摘要；正文必须完成绑定的章节任务、结果变化、卷目标贡献、里程碑动作和章末牵引，且不得引入未授权重大叙事事实。缺失、过期或不一致均为 `FAIL`，不得以 `WARN` 或自动改写大纲继续。

已发布章节事实不可修改。规划内容只能由 `修订卷规划 ARC-NNN` 在审计本卷全部剩余章节、取得用户确认并递增修订号后修改；普通章节事务只可更新完成状态和统计字段。

## 1. 构思

1. 读取 `outline.md`、最近章节摘要、人物状态和伏笔；按场景需要补充力量、库存、时间线与地理。
2. 从冻结契约定位唯一所属卷、卷目标、当前里程碑和本章执行契约；任何摘要不一致立即停止。
3. 生成一个受约束的章节执行方案，规划 3-5 个场景。场景顺序、冲突呈现和信息揭示方式可以变化，但不得改变绑定结果。
4. 检查前情承接、伤势、消耗、战力、时空、人物动机、信息差、卷目标贡献和里程碑截止章。
5. 每章必须具备有效冲突、结果变化和章末牵引；卷内前三章依次完成冲突切入、首次反馈和卷目标锁定。
6. 规划缺陷、事实冲突、逻辑死锁或无法在固定区间内完成卷目标时暂停，不得临时新增支线、增章或修改卷目标。

`构思第 N 章` 到此结束，并遵守 `INV-TRANSACTION-001`。

## 2. 初稿与文本处理

1. 将初稿写入 `chapters/.staging/TX-CH-NNNN-RNN/CH-NNNN-标题.txt`。
2. 按 `chapter-polish.md` 执行一次纯文本润色。
3. 检查字数；不足 2000 字时依据既有细纲补全感官层次、动作因果或必要对话，不得引入新设定。
4. 内容补全后再次执行文本润色。

## 3. 最终门禁

所有检查都针对最后一次润色后的 staging 文件：

1. 字数门禁：不少于 2000 字并输出分段统计。
2. 格式门禁：`INV-CHAPTER-001`、风格黑名单和文件格式均通过。
3. 叙事完整性：不存在无法由确定性模式覆盖的作者、读者、剧情安排或外部镜头调度。
4. 六维审计：体系、战力、时间、物品、地理和人物行为均有文件或实体 ID 依据。
5. 逻辑闭环：核对消耗、伤势、信息差、叙事线索与大纲事件；正式状态变更满足 `INV-FORESHADOW-001`。
6. 剧情对齐：逐项证明正文完成绑定的章节任务、结果变化、卷目标贡献、里程碑动作和章末牵引，且没有未授权重大叙事事实。
7. 留存结构：开篇承接、有效冲突、核心卖点积累、结果变化与章末牵引齐全；留存质量可警告并重写，但不得授权剧情偏离。
8. 单章套路扫描：命中黑名单时警告并修正，不以主观原创评分替代周期审计。

自动修正最多 3 轮。任何必需门禁仍为 ❌ 时，正文保留在 staging，事务失败且不得生成正式 World Bible 变更。

## 4. 准备提交

门禁通过后在事务 staging 中生成 World Bible 候选文件与变更集，必须包含目标文件、实体 ID、字段动作、旧值、新值、来源章节、摘要和幂等键。章节事务对 `outline.md` 只允许把本章状态改为已发布并更新统计，不得新增、删除、重排或改写未来章节契约。发现事实冲突时停止，不发布章节。

## 5. 提交与收尾

事务执行器按 `state-management.md` 校验必需阶段、证据和全部目标基线，再发布正文并回写 World Bible；后置一致性通过后按 `archiving-spec.md` 判断条件归档。只有执行器提交及后置校验通过，章节事务才可标记为完成。

## 叙事线索

悬念钩子与伏笔的定义、候选边界、状态跃迁、紧迫度和证据要求统一遵守 [foreshadowing-spec.md](foreshadowing-spec.md)。本规范只决定其在章节流程中的调用时机，不复制领域规则。
