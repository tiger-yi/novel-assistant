# 🧠🖋️ ReAct 单章创作工作流规范 (Phase: Plan & Draft)

**触发条件**：用户精确发出“开始第 N 章”、“构思第 N 章”或“写第 N 章”（N 为具体数字1-100）时，**立即**启动此流程。
**执行要求**：本规范分为两个阶段：**Phase 1 (构思)** 和 **Phase 2 (撰写)**。AI 必须严格按顺序执行，在 Phase 1 完成后，**自动**选择推荐的剧情分支并直接进入 Phase 2。

# Phase 1: 逻辑构思阶段 (Logic Blueprint)

## 第零步：TODO (任务规划)
**目的**：确保本章剧情严格同步世界观 Bible 文件，覆盖主线、前情、角色、战力、资源、时间、地形全维度。

1. [ ] **核心检索 (Core Context)**：
   - `world/outline.md`：提取当前卷主线进度。
   - `world/chapter-summary.md`：提取前1-2章的核心摘要与“下一章承接”钩子。
   - `world/characters.md`：锁定本章登场角色的当前状态。
2. [ ] **按需检索 (On-Demand Context)**：仅当剧情涉及特定元素时调用。
   - **战斗章节** -> `world/power.md` & `world/inventory.md`
   - **伏笔回收** -> `world/timeline.md`
   - **环境转换** -> `world/geography.md`
3. [ ] **定义本章核心任务**：精确1个主线推进、1个爽点、1个世界观展示、1个伏笔回收。
4. [ ] **输出3-5个核心场景表格**：每个场景标题+核心动作+2个关键锚点。
5. [ ] **提取3个核心看点**和**2-3个新伏笔预埋点**。
6. [ ] **生成2-3个剧情分支选项表格**：每个选项描述核心事件+爽点/冲突+后续影响，标记1个⭐推荐选项。

## 第一步：Thought (多维推演)
**目的**：脑内模拟3轮完整剧情（每轮覆盖开-中-结），识别并规避至少3类指定逻辑陷阱：(1)角色OOC（e.g., 谨慎主角突然莽撞）；(2)资源违规（e.g., 用光库存）；(3)战力崩坏（e.g., 无代价越2境界）；(4)剧情断层（e.g., 未承接上章结尾）。

- **剧情锚点同步**：从`outline.md`定位本章类型（铺垫/小高潮/转折/收尾，必选1）；从`timeline.md`必回收2-3个具体伏笔（e.g., “师妹失踪线索、灵兽蛋孵化”）。
- **前情连贯性核验**：从`chapter-summary.md`验证剧情承接（e.g., “上章结尾重伤，本章开篇必须处于疗伤或带伤逃亡状态，绝不可满血跳跃”）。
- **角色逻辑核验**：从`characters.md`验证主角心理（e.g., “冷静度8/10，支持低风险冒险”）；反派/配角智商检查（基于信息不对称，如反派不知主角底牌，非全知水准）。
- **资源与环境约束**：从`inventory.md`精确库存（e.g., “爆裂符剩余0，无法使用”）；从`geography.md`量化影响（e.g., “雨地减速20%、狭窄地形禁AOE群战”）。
- **力量平衡审计**：从`power.md`验证（e.g., “筑基中期vs金丹初期，越阶需代价如燃烧寿元50年或灵力耗尽”）。

## 第三步：Observation (破坏性审计)
**目的**：逐项审计4检查，必须全✅方可通过；任何❌立即触发Loopback。

- **强制审计清单**（表格输出，每项结果✅/❌+1句说明）：
  | 检查项       | 结果 | 说明                                   |
  |--------------|------|----------------------------------------|
  | 连贯检测    | ✅/❌ | 完美承接上章结尾钩子，无断层跳跃或场景瞬移 |
  | 冲突检测    | ✅/❌ | 无瞬移/医学奇迹（e.g., 断肢须疗伤3天） |
  | 体系纯度    | ✅/❌ | 纯修仙术语（禁魔力/HP/百分比血条）     |
  | 战力&资源   | ✅/❌ | 越2大境界必Fail；库存精确匹配无超支   |
  | 爽点/节奏   | ✅/❌ | 情绪峰值≥3处（高潮/反转/释压），无水文≥200字描述 |

- **修正机制 (Retry Policy)**：
  1.  **自动修正**：若检测到逻辑冲突，尝试自我修正（Max Retries: 3）。
  2.  **人工干预**：若 3 次修正仍失败，停止 Loopback，输出“⚠️ 逻辑死锁警告”及具体冲突点，请求用户决策（忽略/手动调整）。

# Phase 2: 沉浸撰写阶段 (Drafting)

**触发条件**：Phase 1 审计通过并自动选择推荐分支后立即触发。

## 第一步：Thought (深度构思)
**目的**：构建本章“虚拟片场”模型，明确全局基调、感官锚点、状态限制、信息边界和视觉节奏。
*   **风格对齐**：
    *   **全局基调**：读取 `world/outline.md` “题材赛道”（爽文/虐文）和“情绪闭环”，强制一致（爽文：短句≥60%、反击描写≥4处；虐文：环境渲染≥30%、心理独白≥5句）。
    *   **局部微调**：若用户输入有指令（如“压抑”），本章仅调整：心理权重+40%、语速降至长句占比≥50%。
*   **感官与环境锚点**：
    *   从 `world/geography.md` 提取3项物理属性（地形、天气、光源）。
    *   **干扰元素**：指定1项动态干扰（示例：伤口血迹导致脚步滑移0.3秒）。
*   **状态与生理限制**：
    *   查询 `world/characters.md` 和 `world/inventory.md`，列出2-4项即时负担（示例：灵力枯竭→动作迟滞，每招慢0.2秒）。
*   **心理动机与信息差**：
    *   **信息边界**：表格格式列出（角色|已知信息|未知信息），动机锚点：1句核心驱动力（示例：反派“杀意主导，忽略侧翼”）。
*   **节奏与基调**：
    *   **高潮段落**：强制使用短句列阵（Short-Sentence Staccato），营造窒息感。
    *   **文戏段落**：长短句交替，模拟呼吸节奏。
*   **视觉节奏**：每段保持短小精悍（手机屏友好）；关键动作独立成段。

## 第二步：Action (精准描写 - 沉浸叙事)
**核心目的**：撰写正文，追求**高密度动作流 (High-Density Action Flow)**与**沉浸式物理反馈**。
*   **风格控制**：
    *   **少对话，多描写**：非必要不开口，用微表情和肢体语言替代水词。
    *   **物理反馈**：确保每一次互动都有环境或生理的回响（e.g., 拳风震碎发梢）。
*   **量化转换规则 (重要)**：
    *   禁止在正文出现任何数值、百分比或现代度量单位（除非系统流界面）。
    *   示例：❌“灵力剩余20%” -> ✅“丹田已近干涸，每一次提气都带出暗红的血丝”。
*   **称谓与编号规范（正文可读性）**：
    *   **禁止**在正文直接出现内部编号/代号（如：R16、C-12、N-07）。使用“**显名 + 方位/结构 + 特征**”的叙事称谓。
        *   示例：❌“R16盲井” → ✅“暗渠风孔后的那口盲井”；❌“C-12节点” → ✅“官巷绣铺后坊旧井的牙根死扣”。
    *   若剧情确需在角色内心/对话中出现编号信息（档案/口供/推演场景），**首次**必须以自然语境释义清楚编号所指，**随后统一使用叙事称谓**替代；土著角色**禁止**现代编号口吻。
    *   与 World Bible 的同步：在 Observation 的“数据预告”中标注“正文称谓 ↔ Bible 内部编号”的映射，由“更新世界”流程回写；
      提交前执行代号残留自检（建议检索：R\\d+、C-\\d+、N-\\d+）。
*   **物理受力与环境连续性**：
    *   **强制**：每冲突描写含环境反馈（示例：非“快速奔跑”，而“脚踏碎青砖，泥水溅膝2尺高”）。
    *   **连续性**：前段破坏物（如碎桌）后段必复用≥2次（示例：追逐绕过木堆绊脚）。
*   **动作与生理细节**：
    *   **Show Don't Tell**：严禁“感到/觉得/似乎”，替换为具体的生理颤动、肌肉紧绷或呼吸节奏变化。
*   **对话质感与人设**：
    *   **动作引导**：全对话配动作（❌“他说” → ✅“刀落风啸：‘死！’”）。
    *   **潜台词**：主角冷酷≤8字/句；配角市侩含利益词≥1次/句。
*   **战力合规性**：
    *   遵 `world/power.md`，阶位差体现量化压制（示例：筑基压炼气→呼吸滞0.5秒、出力降30%）。
*   **存储目录**：所有正文章节必须统一输出至 `chapters/` 目录。
*   **命名规范**：严格采用 `XXXX-章节标题.md` 格式（XXXX 为四位数字编号，不足四位由 0 补齐，支持万章规模）;其中章节标题字数随机2-8位
    * **示例**：`0001-灭村.md`、`0006-雷降药铺.md`。
*   **存储与命名**：统一输出至 `chapters/` 目录，格式 `XXXX-章节标题.md`，字数1500-2500字。

## 第三步：Observation (质量审计)
**目的**：执行自查清单。
*   **检查章节**: 确认章节在 `chapters/` 目录下已存在。
*   **逻辑回溯**：
    1.  ✅/❌ **数据闭环**：核对 `world/inventory.md` 消耗；核对 `world/characters.md` 伤势。
    2.  ✅/❌ **信息差**：确认无全知视角泄露。
*   **去 AI 味脱敏 (核心词库)**：
    1.  ✅/❌ **无总结结尾**：严禁“这一战，不仅是...更是...”、“...的开始”。
    2.  ✅/❌ **禁用词清理**：禁止出现：显然、显而易见、不得不说、交织、响彻云霄、缓缓、这一刻、紧接着、随之、旋即、璀璨夺目、命运齿轮、由此可见、预示、升华、不屈、余波、波动、似乎、仿佛。
    3.  ✅/❌ **代号清理**：正文不得保留内部编号/代号（如：R16、C-12、N-07）。若需表达，须已在首次处完成释义，之后以叙事称谓替代；发布前统一清除编号痕迹。
*   **自动流转 (更新世界)**：
    1.  **修正策略**：针对 AI 味重或违禁词，尝试自动重写对应段落（Max 3次）。若多次修正无效，标记“⚠️ 待人工润色”并继续执行归档。
    2.  **若审计 Pass**：自动执行“更新世界”指令。

## 写作禁忌 (违者Hotfix)
1. 总结结尾：禁“奠定/预示/欲知后事”。
2. 上帝视角：禁“这不仅是战斗，更是信念碰撞”。
3. 数据堆砌：非面板视角，禁直接列敌数据。
4. 禁用高频词：缓缓、这一刻、似乎、仿佛等。
