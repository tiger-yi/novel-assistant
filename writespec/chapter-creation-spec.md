# 单章创作工作流

`创作第 N 章` 自动执行完整流程；`构思第 N 章` 只执行构思与逻辑审计并停止。

## 1. 构思

1. 读取 `outline.md`、最近章节摘要、人物状态和伏笔；按场景需要补充力量、库存、时间线与地理。
2. 规划 3-5 个场景，至少包含主线推进、兑现点、世界观展示和伏笔动作。
3. 生成 2-3 个分支，标出推荐分支及其代价。
4. 检查前情承接、伤势、消耗、战力、时空、人物动机和信息差。
5. 完整创作模式自动采用推荐分支；只有事实冲突、逻辑死锁或修订已发布章节时暂停。

`构思第 N 章` 到此结束，不创建事务日志，也不写任何文件。

## 2. 初稿与文本处理

1. 将初稿写入 `chapters/.staging/CH-NNNN-标题.txt`。
2. 按 `chapter-polish.md` 执行一次纯文本润色。
3. 检查字数；不足 2000 字时依据既有细纲补全感官层次、动作因果或必要对话，不得引入新设定。
4. 内容补全后再次执行文本润色。

## 3. 最终门禁

所有检查都针对最后一次润色后的 staging 文件：

1. 字数门禁：不少于 2000 字并输出分段统计。
2. 格式门禁：禁用符号、Markdown、风格黑名单和文件格式均通过。
3. 六维审计：体系、战力、时间、物品、地理和人物行为均有文件或实体 ID 依据。
4. 逻辑闭环：核对消耗、伤势、信息差、伏笔与大纲事件。
5. 单章套路扫描：命中黑名单时警告并修正，不以主观原创评分替代周期审计。

自动修正最多 3 轮。任何必需门禁仍为 ❌ 时，正文保留在 staging，事务失败且不得生成正式 World Bible 变更。

## 4. 准备提交

门禁通过后生成 World Bible 变更集，必须包含目标文件、实体 ID、字段动作、旧值、新值、来源章节和幂等键。发现事实冲突时停止，不发布章节。

## 5. 提交与收尾

按 `state-management.md` 发布正文并回写 World Bible，执行后置一致性校验，再按 `archiving-spec.md` 判断条件归档。只有提交后置校验通过，章节事务才可标记为完成。

## 伏笔规则

- 优先推进 P0，其次 P1；连续 3 章未推进给出预警。
- 新伏笔必须有稳定 ID、来源章节和预计回收范围。
- 构思阶段只产生候选；正式状态只在提交阶段写入 `hooks.md`。
