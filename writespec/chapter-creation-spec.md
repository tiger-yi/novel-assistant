# 单章创作工作流

`创作第 N 章` 自动执行完整流程；`构思第 N 章` 只执行构思与逻辑审计并停止。

## 不变量

### INV-CHAPTER-001 正文呈现边界

staging、正式正文及其历史呈现修订必须同时满足以下规则：

1. **禁止面板化符号**：无例外禁止 `【】`、`[]`、`（）`、`《》`、Markdown 标题/列表/表格和加粗标记；非对话不得使用引号。
   - 只有当前场景内真实发声、并由动作、神态、声音或说话人引导的在场台词允许使用引号。
   - 回忆、转述、概括他人曾说过的话，时代口号、断言、称呼、术语、心声或强调词，均属于非对话，不得用引号包装。
   - 引述他人话语必须做等义呈现：可改为名词化概括、引述标记、变体引述或间接转述；只有原话正在场景内被人说出口时，才可还原为在场台词。
   - 等义整改不得改变说话来源、事实语义、人物知情范围、叙事线索证据或剧情事实；若引述短语承担 `HOOK-*`/`SEED-*` 正文证据，改后仍须能支撑原证据表述。
   - 句末破折号和省略号必须服务明确语义：`——` 仅用于话语被打断、话锋悬停或场面压断；`……` 仅用于迟疑、吞话、余音或情绪下沉。正常说完的对白不得用二者制造假悬念、假停顿或替代动作描写。
   - 正文叙述中原则上不得用破折号承接揭示、转折或动作结果；应优先用短句、动作、感官变化和人物反应完成表达。只有确有语义截断且无法自然改写为句号、逗号或动作承接时，才可保留破折号。
2. **禁止内部代号**：正文不得出现 `CH-*`、`ARC-*`、`HOOK-*`、`SEED-*`、`EVT-*`、`TX-*`、`CHAR-*`、`ITEM-*`、`LOC-*`、`FAC-*`、`GOAL-*`、`MS-*` 等 Harness ID，也不得出现大小写不限的裸字母数字代号，如 `R16`、`C-12`、`n-07` 或 `room12`。允许“七号矿井”“甲字三号牢房”等自然中文称谓。
3. **禁止章节结构引用**：正文不得出现 `第X章`、`上一章`、`上章`、`本章`、`下一章`、`下章`、`前文` 或 `后文`；必须改写为具体时间、事件或自然承接。
4. **禁止叙事层泄漏**：正文不得暴露作者、读者、剧情安排、创作过程或外部镜头调度。确定性模式之外的“读者应该已经发现”“作者暂且不表”“剧情需要”“镜头转回主角”等表达由 `narrative-integrity` 语义门禁判断。

确定性校验必须报告本 INV ID、行号和命中项；语义门禁只接受 `PASS`。命中后由 Agent 结合上下文重写，最多三轮，不得盲目替换。已发布章节只能通过 `迁移正文呈现` 的授权子事务做等义呈现修订，不得改变剧情事实。

### 转述表达选择（普通规范）

本节为 `INV-CHAPTER-001` 的非对话引号边界提供执行指导，不新增确定性阻断条件。判断依据是话语是否正在当前场景真实发声，而不是它是否位于另一段对白之内；对白中的回忆、旧话和他人话语转述仍属于非在场引述。

按叙事目的依次选择：

1. 只需交代盘问、告诫或争执曾经发生时，使用事件概括。例如：`守门人拦住他盘问来路。`
2. 需要保留问答因果或人物应变时，默认使用间接转述。例如：`守门人问他是不是庄上的，他说自己前来送货，这才获准离开。`
3. 原措辞本身承担线索、口号、双关或跨段回声时，使用自然句法中的名词化概括、引述标记或变体引述，不用引号包装，也不得机械套用固定标记词。例如：`他始终记得师父不可回头的告诫。`
4. 声线、口气或措辞本身具有场景价值时，可由当前人物明确当场模仿。必须用动作、神态、声音或“学着某人”等引导证明这句话正在当前场景真实说出口；不得为了保留引号虚构表演或新增事实。例如：`他压低嗓子，学着守门人的口气：“从哪里来的？”`

所有方式都必须保留说话来源、事实语义、人物知情范围和叙事线索证据。`narrative-integrity` 必须提交 `key: reported_speech_audit` 的语义证据，记录扫描范围、命中位置、每处采用的策略或合法保留理由以及未解决项；无命中时仍须记录完整扫描，未解决项非空不得返回 `PASS`。

### INV-PLOT-001 冻结大纲契约

`world/outline.md` 必须包含状态为 `frozen` 的 `novel-harness/outline/v2` 契约：全书卷路线图使用连续且固定的章节闭区间，当前卷具有可验收卷目标、3-5 个带截止章节的有序里程碑，以及覆盖整卷的章节执行契约。章节事务必须绑定开始时的大纲修订号、正式文件摘要、所属卷、卷目标、章节 ID 和章节契约摘要；正文必须完成绑定的章节任务、结果变化、卷目标贡献、里程碑动作和章末牵引，且不得引入未授权重大叙事事实。缺失、过期或不一致均为 `FAIL`，不得以 `WARN` 或自动改写大纲继续。

已发布章节事实不可修改。规划内容只能由 `修订卷规划 ARC-NNN` 在审计本卷全部剩余章节、取得用户确认并递增修订号后修改；普通章节事务只可更新完成状态和统计字段。

## 1. 构思

1. 读取 `outline.md`、最近章节摘要、人物状态和 `world/hooks.md` 中的活跃悬念钩子与伏笔；按场景需要补充力量、库存、时间线与地理。
2. 从冻结契约定位唯一所属卷、卷目标、当前里程碑和本章执行契约；任何摘要不一致立即停止。
3. 生成自然中文章节标题，并与已发布章节文件名、当前活动 staging 文件名和章节摘要中的既有标题去空白比对；重名必须换题。
4. 生成一个受约束的章节执行方案，规划 3-5 个场景。场景顺序、冲突呈现和信息揭示方式可以变化，但不得改变绑定结果。
5. 检查前情承接、伤势、消耗、战力、时空、人物动机、信息差、卷目标贡献和里程碑截止章。
6. 生成六维世界观风险表，逐项覆盖体系纯度、战力平衡、时间线、物品消耗、地理跨度和人物行为；每项必须列出引用文件或实体 ID、预计正文证据、回写动作和风险结论。
7. 生成叙事线索处理表，逐项覆盖本章涉及的活跃 `HOOK-*`、`SEED-*`、到期或逾期线索、新候选钩子和新候选伏笔；候选只绑定场景和预期证据，不分配正式 ID。
8. 每章必须具备有效冲突、结果变化和章末牵引；卷内前三章依次完成冲突切入、首次反馈和卷目标锁定。
9. 规划缺陷、标题重名、事实冲突、逻辑死锁、世界观熔断项、叙事线索回收与既有证据冲突，或无法在固定区间内完成卷目标时暂停，不得临时新增支线、增章或修改卷目标。

`构思第 N 章` 到此结束，并遵守 `INV-TRANSACTION-001`。

## 2. 初稿与文本处理

1. 将初稿写入 `chapters/.staging/TX-CH-NNNN-RNN/CH-NNNN-标题.txt`。
2. 初稿必须按六维世界观风险表处理力量术语、战力依据、时间流逝、物品消耗、地理信息和人物动机；不得为通过审计临时新增 World Bible 未授权事实。
3. 初稿必须按叙事线索处理表把候选、推进、解决或回收动作落到具体场景；正文不得暴露 `HOOK-*`、`SEED-*` 等内部 ID。
4. 按 `chapter-polish.md` 执行一次纯文本润色。
5. 按 `chapter-polish.md` 执行 `signing-first-impression-risk` 门禁；`WARN` 可在授权边界内自动修复，`FAIL` 按 L3 分层和四档自动化阻断分级进入自动修复、自动路由提交、候选复核或人工确认。
6. 按 [reader-evaluation.md](reader-evaluation.md) 执行读者评价门禁；可直接处理的扣分维度和对应段落先局部受限重润色，结构性或世界状态建议必须按 `AUTO_ROUTE_COMMIT`、`AUTO_ROUTE_REVIEW` 或 `HUMAN_REQUIRED` 路由，不得在当前评价阶段越权改正文或 World Bible。
7. 检查字数；低于 2300 字时依据既有细纲补全感官层次、动作因果或必要对话，高于 2800 字时压缩重复段落和低价值描写，不得引入新设定或改变事实。
8. 内容补全后再次执行文本润色。

## 3. 最终门禁

所有检查都针对最后一次润色后的 staging 文件：

1. 读者评价门禁：三读者画像聚合分、单画像硬下限、复评轮次和 artifact 证据均满足 `reader-evaluation.md`。
2. 签约首感风险门禁：`signing_first_impression_risk` 证据覆盖开篇、主要场景入口和章末牵引；`PASS` 或 `WARN` 可继续，`FAIL` 不得发布正文。
3. 字数门禁：2300-2800 字并输出分段统计。
4. 标题唯一性：最终 staging 文件名中的章节标题与已发布章节、当前活动 staging 和章节摘要既有标题不重名。
5. 格式门禁：`INV-CHAPTER-001`、风格黑名单和文件格式均通过。
6. 叙事完整性：不存在无法由确定性模式覆盖的作者、读者、剧情安排或外部镜头调度。
7. 六维审计：体系、战力、时间、物品、地理和人物行为均有文件或实体 ID 依据。
8. 逻辑闭环：核对消耗、伤势、信息差、叙事线索与大纲事件；正式状态变更满足 `INV-FORESHADOW-001`。
9. 剧情对齐：逐项证明正文完成绑定的章节任务、结果变化、卷目标贡献、里程碑动作和章末牵引，且没有未授权重大叙事事实。
10. 留存结构：开篇承接、有效冲突、核心卖点积累、结果变化与章末牵引齐全；留存质量可警告并重写，但不得授权剧情偏离。
11. 单章套路扫描：命中黑名单时警告并修正，不以主观原创评分替代周期审计。

自动修正最多 3 轮。任何必需门禁仍为 ❌ 时，正文保留在 staging，事务失败且不得生成正式 World Bible 变更。

## 4. 准备提交

门禁通过后在事务 staging 中生成 World Bible 候选文件与变更集，必须包含目标文件、实体 ID、字段动作、旧值、新值、来源章节、摘要和幂等键。世界观相关变更必须回指六维审计结论；战力、物品、时间、地理或人物状态变更必须有正文证据和对应 World Bible 依据，战力胜负必须显式满足 `INV-POWER-001`。叙事线索候选转正式、推进、解决或回收时，还必须包含动作、合法前置状态、正文证据和 `叙事线索 ID + 动作 + 来源章节 ID` 幂等键；没有正文证据的候选不得写入 `hooks.md`。章节事务对 `outline.md` 只允许把本章状态改为已发布并更新统计，不得新增、删除、重排或改写未来章节契约。发现事实冲突时停止，不发布章节。

## 5. 提交与收尾

事务执行器按 `state-management.md` 校验必需阶段、证据和全部目标基线，再发布正文并回写 World Bible；后置一致性通过后按 `archiving-spec.md` 判断条件归档。只有执行器提交及后置校验通过，章节事务才可标记为完成。

## 叙事线索

悬念钩子与伏笔的定义、候选边界、状态跃迁、紧迫度和证据要求统一遵守 [foreshadowing-spec.md](foreshadowing-spec.md)。本规范只决定其在章节流程中的调用时机，不复制领域规则。

叙事线索处理表是 `构思第 N 章` 和完整章节事务的必需构思产物，至少包含：线索类型、现有 ID 或候选标记、当前状态、本章动作、正文承载场景、预计或实际证据、预计解决/回收范围、风险结论。不涉及本章的活跃线索也必须给出“保持不动”的理由；到期中或已逾期线索必须给出处理、警告或暂停结论。

## 世界观审计

六维世界观风险表是 `构思第 N 章` 和完整章节事务的必需构思产物，至少包含：审计维度、涉及文件或实体 ID、本章风险、正文承载场景、预计或实际证据、需回写目标、结论。战力维度必须单列双方境界、完整大境界差距、既有底牌或克制依据、正文代价和 `INV-POWER-001` 结论；任一熔断项必须先改方案或暂停，不得留到提交阶段用 World Bible 补丁掩盖。
