# 🖋️ ReAct 撰写正文规范 (V2.1 精准优化版)
**触发条件**：用户精确发出“开始撰写” 或 “写”时，**立即**启动此流程
当流程进入 **撰写阶段** 时，AI 必须严格按以下四个子步骤顺序执行，每步输出独立标题和指定格式内容，确保总字数控制在1500-2500字（正文占比85%以上）。

## 第零步：TODO (执行规划 - 任务清单化)
**核心目的**：将 `world/outline.md` 中的章节大纲转化为8项具体可执行写作任务，输出复选框清单，每项后附1-2句具体执行标准（总输出≤200字）。

*   **必备任务项**（逐项核对并标记）：
    0.  [ ] **风格对齐**：从 `world/outline.md` 提取情绪基调（爽文：主角逆转占比≥70%；虐文：挫败占比≥60%），并应用用户输入中的特殊指令（如“压抑”：增加心理独白≥3处，降低动作描述速度20%）。
    1.  [ ] **环境与氛围**：定义3-5个感官锚点（视觉：昏黄灯火；听觉：雨打瓦片声；触觉：湿冷空气），并添加1个干扰元素（示例：远处更夫敲梆声，间隔5-10秒干扰主角专注）。
    2.  [ ] **生理与限制**：列出角色2-4项即时生理负担（示例：左臂旧伤导致挥剑偏移10cm、灵力剩30%引起呼吸急促，每分钟喘息描述≥2次）。
    3.  [ ] **信息差核对**：定义各方视角边界（主角知晓：自身灵力值；反派不知：主角隐藏底牌；路人仅知表面冲突），禁止任何全知叙述。
    4.  [ ] **动作与受力**：规划核心冲突3-5个物理反馈点（示例：剑气碰撞震裂青砖溅泥水高3m、法则对撞主角后退2步）。
    5.  [ ] **情绪侧写**：预埋精确2处（1处路人震惊：围观者瞳孔放大脱口“怪物！”；1处反派心理：犹豫0.5秒，暗想“此子底牌未尽”）。
    6.  [ ] **去 AI 味审计**：扫描并排除5类高频问题（总结结尾、显然/显而易见、璀璨夺目、交织、响彻云霄），替换为具体描写。
    7.  [ ] **数据预告**：列出3-5项精确变更（示例：主角境界升炼气2层、消耗灵石2枚、时间推移2小时，需回写 `world/bible.yaml`）。

## 第一步：Thought (深度构思 - 状态同步)
**核心目的**：构建本章“虚拟片场”模型，输出 bullet point 格式，每点≤50字，总输出≤400字。

*   **风格对齐**：
    *   **全局基调**：读取 `world/outline.md` “题材赛道”（爽文/虐文）和“情绪闭环”，强制一致（爽文：短句≥60%、反击描写≥4处；虐文：环境渲染≥30%、心理独白≥5句）。
    *   **局部微调**：若用户输入有指令（如“压抑”），本章仅调整：心理权重+40%、语速降至长句占比≥50%。
*   **感官与环境锚点**：
    *   从 `world/geography.md` 提取3项物理属性（地形、天气、光源）。
    *   **干扰元素**：指定1项动态干扰（示例：伤口血迹导致脚步滑移0.3秒）。
*   **状态与生理限制**：
    *   查询 `world/characters.yaml` 和 `world/inventory.md`，列出2-4项即时负担（示例：灵力枯竭→动作迟滞，每招慢0.2秒）。
*   **心理动机与信息差**：
    *   **信息边界**：表格格式列出（角色|已知信息|未知信息），动机锚点：1句核心驱动力（示例：反派“杀意主导，忽略侧翼”）。
*   **节奏与基调**：高潮短句（≤10字/句，≥70%）；文戏长短交替（平均15字/句）。
*   **视觉节奏**：每段≤3行（手机屏高标准，240px）；关键动作独立段，首行缩进2空格。

## 第二步：Action (精准描写 - 沉浸叙事)
**核心目的**：撰写正文，物理反馈频率≥每200字1次，总动作描写≥40%，对话占比≤20%。

*   **物理受力与环境连续性**：
    *   **强制**：每冲突描写含环境反馈（示例：非“快速奔跑”，而“脚踏碎青砖，泥水溅膝2尺高”）。
    *   **连续性**：前段破坏物（如碎桌）后段必复用≥2次（示例：追逐绕过木堆绊脚）。
*   **动作与生理细节**：
    *   **Show Don't Tell**：禁“感到/觉得/似乎”（替换：脊背冷汗浸衣、胃痉挛翻腾、指节发白）。
*   **对话质感与人设**：
    *   **动作引导**：全对话配动作（❌“他说” → ✅“刀落风啸：‘死！’”）。
    *   **潜台词**：主角冷酷≤8字/句；配角市侩含利益词≥1次/句。
*   **战力合规性**：
    *   遵 `world/power.md`，阶位差体现量化压制（示例：筑基压炼气→呼吸滞0.5秒、出力降30%）。
*   **存储目录**：所有正文章节必须统一输出至 `chapters/` 目录。
*   **命名规范**：严格采用 `XXXX-章节标题.md` 格式（XXXX 为四位数字编号，不足四位由 0 补齐，支持万章规模）;其中章节标题字数随机2-8位
    * **示例**：`0001-灭村.md`、`0006-雷降药铺.md`。
*   **正文输出**：根据章节命名创建文件,**必须**将文章写入磁盘

## 第三步：Observation (质量审计 - 编辑自查)
**核心目的**：逐项检查10点清单，若任何Fail则触发Hotfix，总输出≤300字。
*   **检查章节**: 确认章节在 `chapters/` 目录下已存在。
*   **逻辑回溯**：
    1.  ✅/❌ **数据闭环**：道具查 `world/inventory.md`，用后扣量（示例：灵石-2）。
    2.  ✅/❌ **伤势连续**：旧伤影响覆盖率≥80%。
    3.  ✅/❌ **信息差**：无全知泄露。
*   **去 AI 味脱敏**：
    1.  ✅/❌ **无总结结尾**：章末无“明白了/风暴”等。
    2.  ✅/❌ **句式律动**：短句≥50%，无排比堆砌。
    3.  ✅/❌ **词汇净化**：禁15词（显然、显而易见、不得不说、交织、响彻云霄、缓缓、这一刻、紧接着、随之、旋即、璀璨夺目、命运齿轮、由此可见、预示、升华）。
*   **Hotfix协议**：若≥1 Fail，添加 **4. Hotfix** 子节，提供修正片段（≤200字，标明修改位置，如“替换第X段”）。
*   **数据更新预告**：列表3-5项（示例：“world/characters.yaml: 主角境界=炼气2层；world/inventory.md: 灵石-=2”）。

## 写作禁忌 (强制负向规则，违者Hotfix)
1.  **总结结尾**：禁“奠定/预示/欲知后事”。
2.  **上帝视角**：禁“这不仅是战斗，更是信念碰撞”。
3.  **数据堆砌**：非面板视角，禁直接列敌数据。
4.  **滥用缓缓**：替换“睁眼/吐气”。
5.  **滥用这一刻**：禁“时间静止”等。
6.  **额外**：段落>3行重分；对话无动作标签重写；爽文逆转<3次重构。
