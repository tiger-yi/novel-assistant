# 悬念钩子与伏笔管理规范

本规范是悬念钩子与伏笔定义、状态跃迁、证据、审计及归档语义的唯一权威。`world/hooks.md` 是两类叙事线索的活跃注册表，不包含情绪爆发点规划。

## 1. 领域对象

### 悬念钩子

制造近期阅读驱动力的未解决问题、危机或承诺。钩子可以直接解决，不一定形成伏笔，使用 `HOOK-NNNN`。

### 伏笔

已写入正文、用于支撑未来揭示或反转的可追踪事实。伏笔必须存在埋设证据，并在回收时证明兑现结果与原线索的因果连接，使用 `SEED-NNNN`。

### 情绪爆发点

情绪爆发点是剧情规划事件，使用 `EVT-NNNN`。未来规划属于 `outline.md`，发生事实由 `timeline.md` 或 `chapter-summary.md` 记录，不写入 `hooks.md`。

## 2. 不变量

### INV-FORESHADOW-001 证据化状态跃迁

悬念钩子或伏笔进入正式状态、推进、解决、回收、放弃或取消时，必须同时具备稳定 ID、合法前置状态、来源章节和对应正文证据。状态变更以 `叙事线索 ID + 动作 + 来源章节 ID` 判重，恢复或重复执行不得创建重复记录或重复跃迁。违反任一条件必须阻断 World Bible 提交。

## 3. 生命周期

候选只存在于构思输出，不写入正式 World Bible。

### 3.1 悬念钩子

正常路径为 `候选 -> 待解决 -> 已解决 -> 已归档`。

- `待解决`：已发布章节明确提出悬念，并有来源章节和证据。
- `已解决`：后续已发布章节给出明确结果。
- `已放弃`：仅在用户明确批准并记录原因后使用，随后可以归档。

### 3.2 伏笔

正常路径为 `候选 -> 已埋设 -> 推进中 -> 已回收 -> 已归档`。没有中间推进时，允许从 `已埋设` 直接进入 `已回收`。

- `已埋设`：已发布章节出现可定位的正文事实。
- `推进中`：后续章节增加或改变读者可见信息；每次推进都追加章节与证据。
- `已回收`：已发布章节兑现伏笔，并记录结果与原线索的因果连接。
- `已取消`：仅在用户明确批准并记录原因后使用，随后可以归档。

## 4. 注册字段

### 4.1 悬念钩子字段

`钩子 ID`、`提出章节`、`悬念描述`、`叙事层级`、`预计解决范围`、`状态`、`提出证据`、`解决章节`、`解决结果`。

### 4.2 伏笔字段

`伏笔 ID`、`埋设章节`、`伏笔描述`、`表面解释`、`真实指向`、`叙事层级`、`预计回收范围`、`状态`、`埋设证据`、`推进记录`、`回收章节`、`回收结果`。

叙事层级仅允许 `主线`、`卷级`、`局部`。预计范围使用章节区间 `CH-NNNN..CH-NNNN`，或使用可验证的卷终边界。

## 5. 紧迫度与审计策略

紧迫度由当前章节与预计解决或回收范围推导，不作为持久字段：

- 当前章节早于范围起点：`未到期`。
- 当前章节位于范围内：`到期中`。
- 当前章节超过范围终点：`已逾期`。

连续三章未推进、进入到期范围或已经逾期均可产生审计警告，但不属于 INV，不得仅凭警告阻断章节事务。每章必须设置新钩子、固定章数必须回收等节奏策略同样不得作为硬性不变量。

## 6. 章节事务

- 构思阶段可以生成候选钩子和候选伏笔，但不得分配正式 ID 或修改 `hooks.md`。
- 正式 ID 在准备变更集时按活跃与归档历史最大编号分别生成；提交阶段确认正文证据存在后写入。
- 推进、解决或回收必须在变更集中列出旧状态、新状态、动作、来源章节、证据和幂等键。
- 回收真相与既有埋设证据冲突时必须停止，不得通过改写 World Bible 掩盖已发布正文冲突。
- 放弃钩子或取消伏笔必须具有当前任务中的明确用户批准。

## 7. 归档

只有 `已解决`、`已放弃`、`已回收` 或 `已取消` 的条目可以按 `archiving-spec.md` 迁移到 `archive/hooks_history.md`。活跃注册表必须保留叙事线索 ID、结果摘要和归档链接；归档记录保留全部来源与状态跃迁证据。
