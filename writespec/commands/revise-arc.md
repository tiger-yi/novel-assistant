# 命令协议: 修订卷规划 (revise-arc)

> **触发格式**: `修订卷规划 ARC-NNN`
>
> **示例**: `修订卷规划 ARC-001`

## 功能

对指定卷中尚未发布的章节执行影响分析并准备最小修订。已发布章节、已发生事实、卷章节区间和已完成里程碑不可修改；无法在剩余固定章节内完成原卷目标时停止并报告，不得自动增章或改写卷目标。

## 前置条件

- `world/outline.md` 满足 `INV-PLOT-001`，指定卷存在。
- 指定卷不是已完成卷，且至少存在一个未发布章节。
- 已发布正文与 World Bible 作为不可修改基线。
- 同一目标不存在进行中的卷规划修订事务。

## 准备阶段

1. 事务执行器解析卷 ID，记录正式大纲基线。
2. 审计该卷全部剩余章节，定位受影响的章节任务、卷目标贡献、关联里程碑和章末牵引。
3. 生成最小差异；不得修改已发布章节契约、固定章节区间、卷目标终态或已完成里程碑。
4. 将修订号递增，重新计算未发布章节契约，保持全书卷间因果连续。
5. 提交 `plan-impact` 证据，逐项列出旧值、新值、影响章节和恢复卷目标的因果路径。
6. 对 staging 大纲运行 `python scripts/validate_outline.py <outline_file>`。

任何冲突、剩余章数不足或门禁失败都必须停止。Agent 只写事务 staging 和 YAML 证据。

## 授权与提交

正式 `world/outline.md` 已存在，因此必须通过事务执行器的逐目标覆盖确认。只有影响分析、`INV-PLOT-001` 和用户确认全部有效时，事务执行器才可提交；提交后大纲重新冻结。普通 `创作第 N 章` 与 `更新世界` 无权修改规划字段。

## 完成输出

报告卷 ID、新修订号、修改的未发布章节、未修改的已发布范围、门禁结果和大纲摘要值。
