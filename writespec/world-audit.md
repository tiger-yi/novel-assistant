# 世界观审计规范 (World Audit)

> 来源: 由原 `chapter-polisher` 技能引用的 `world_audit_spec.md` 转化。

审计必须对照 `world/` 目录下的 8 类 Bible 文件。运行期字段、动作和证据粒度按 `world-bible-contract.md` 判断。任何未定义的“天降名词”均判定为非法；发现事实来源冲突时按 `state-management.md` 停止自动覆盖。

## 战力不变量

### INV-POWER-001 越级取胜上限

角色不得战胜跨越两个及以上完整大境界的对手；“完整大境界”按 `power.md` 的主体系阶梯或跨体系对照计算，不把初期、中期、后期等子阶段单独计为大境界。差距不足两个完整大境界时，取胜仍必须同时具备 World Bible 已有的底牌或克制依据、正文明确支付的代价，以及对应章节与实体 ID 证据。

## 审计基准文件
| 文件 | 用途 |
|------|------|
| outline.md | 剧情大纲、核心设定、题材赛道 |
| power.md | 境界/规则白名单、禁止术语黑名单 |
| characters.md | 角色境界、功法、状态、性格 |
| timeline.md | 纪元时间、主角年龄、大事件 |
| inventory.md | 物品存量、消耗性底牌 |
| geography.md | 地图坐标、移动时速、情报时滞 |
| hooks.md | 活跃的 `HOOK-*` 悬念钩子与 `SEED-*` 伏笔 |
| chapter-summary.md | 前情承接、信息差、状态变化来源章节 |

## 六维审计矩阵
| 维度 | 核心问题 | 审计动作 | 判定标准 |
|------|----------|----------|----------|
| **1. 体系纯度** | 术语是否混用 | 检索 power.md 白名单/黑名单 | ✅通过 / ❌体系污染 |
| **2. 战力平衡** | 是否满足 `INV-POWER-001` | 对照 power.md 境界映射与 inventory.md 底牌消耗 | ✅上限内且依据、代价齐全 / ❌战力崩坏 |
| **3. 时间线** | 闭关/赶路时间是否自洽 | 计算当前年份+剧情流逝 | ✅通过 / ❌时间神隐 |
| **4. 物品消耗** | 道具是否有库存 | 对比 inventory.md 存量 | ✅通过 / ⚠️需扣除 |
| **5. 地理跨度** | 消息传递是否超时 | 查阅 geography.md 通信手段 | ✅通过 / ❌情报漏洞 |
| **6. 人物OOC** | 行为是否符合人设 | 检索 characters.md 性格标签 | ✅通过 / ❌降智/OOC |

## 判定与修正规则
### ✅ 通过
- 逻辑自洽, 无须修改。

### ⚠️ 需更新
- 执行 inventory.md 减法。
- 同步更新相关 Bible 文件。

### ❌ 熔断 (必须重写)
| 错误类型 | 修正要求 |
|----------|----------|
| 体系污染 | 根据白名单强制替换词汇, 修正底层力量逻辑 |
| 战力崩坏 | 跨越硬上限时必须改写胜负或依据既有事实降低有效差距；上限内只能调用已有底牌/克制并补足明确代价，禁止事后新增削弱补丁 |
| 时间神隐 | 合理延长闭关/赶路时长, 更新角色状态 |
| 物品无中生有 | 强制修改为"因缺少底牌而陷入绝境" |
| 情报漏洞 | 增加消息传递时间差, 或引入眼线/监控描写 |
| 人物降智/OOC | 重写行为动机, 增加利益驱动逻辑闭环 |
| 叙事线索断裂 | 依据大纲与 `foreshadowing-spec.md` 修正；不得为通过门禁临时制造无依据伏笔 |

## 审计执行 Checklist
```
[ ] 体系纯度: 扫描力量/规则名词, 对照 power.md 白名单
[ ] 战力平衡: 对比交战双方实力+底牌消耗
[ ] 时间线: 计算当前年份 = timeline记录 + 剧情流逝
[ ] 物品消耗: 核对 inventory.md 库存 > 0
[ ] 地理跨度: 确认消息传递速度符合地图设定
[ ] 人物OOC: 检索 characters.md 核心特征标签
[ ] 叙事线索: 检查 HOOK/SEED 状态、正文证据与预计范围
[ ] 大纲遵从: 对照 outline.md 核心事件是否完成
[ ] 前情承接: 对照 chapter-summary.md 最近 3 章是否存在状态或信息断层
[ ] 引用完整: 跨文件人物/物品/地点/叙事线索是否使用稳定 ID，且目标条目存在
```

每项结论必须附文件名、章节 ID 或实体 ID。此审计属于语义门禁，不能以脚本退出码或“模型认为合理”替代证据。

## 叙事线索审计补充
| 检查项 | 标准 |
|--------|------|
| 钩子处理 | 检查本章是否提出或解决 `HOOK-*`，状态动作是否有正文证据 |
| 伏笔处理 | 检查 `SEED-*` 的埋设、推进或回收是否符合既有铺垫 |
| 状态完整性 | 所有正式跃迁必须满足 `INV-FORESHADOW-001` |
| 紧迫度 | 按预计范围推导未到期、到期中或已逾期；警告不单独阻断事务 |

## 大纲遵从度检查
| 检查项 | 说明 |
|--------|------|
| 事务绑定 | 大纲修订、文件摘要、卷 ID、卷目标 ID、章节 ID 与章节契约摘要均未过期 |
| 章节任务 | 正文完成绑定任务、核心冲突和结果变化 |
| 卷目标贡献 | 本章结果形成契约声明的可验证卷目标贡献 |
| 里程碑 | 不提前越过前置里程碑，且不晚于固定截止章 |
| 重大叙事事实 | 未规划的重要人物、势力、能力、道具、关系、信息、支线或长期线索数量为 0 |
| 章末牵引 | 存在服务主线的具体牵引；跨章追踪时才登记 `HOOK-*` |
| 灌水检测 | 大量无关描写/重复打斗/停滞进度 |
| 剧情偏离 | 任一绑定结果未完成或出现未授权重大事实即 `FAIL`，满足 `INV-PLOT-001` 后才能继续 |

留存结构缺少开篇承接、有效冲突、结果变化或章末牵引时为 `FAIL`。牵引力度、节奏变化等质量判断可以 `WARN` 并在不改变剧情契约的前提下重写，最多三轮；不得通过临时增加支线或设定提升刺激度。
